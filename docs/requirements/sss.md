## 1. 범위

### 1.1 체계 개요

ARGUS는 소형 드론에 NPU 임베디드 보드를 탑재하여, 지휘부와 통신이 끊긴 상황에서도 온보드에서 지상 표적(전차)을 실시간 탐지·추적하고 대상을 자율 추종하는 체계이다.

본 문서는 체계 수준 요구사항을 정의하는 최상위 기술문서이며, 프로젝트 계획서의 6개 과업을 체계 요구사항으로 정리하였다. 체계 설계(SSDD)와 소프트웨어 요구사항(SRS)은 본 문서를 상위 기준으로 한다.

### 1.2 계획서 과업

| 과업 | 명칭 | 주요 내용 |
|---|---|---|
| 01 | 요구사항과 아키텍처 | 무게·전력·통신 예산, HW와 SW 인터페이스, 데이터 흐름 |
| 02 | NPU 기반 임베디드 AI 환경 구축 | Pi 5와 Hailo-8 연결, 전원 구성, Driver·Runtime·SDK 설치 |
| 03 | 열화상 영상과 YOLOX 탐지 | 영상 수신·전처리·학습, ONNX 변환, NPU 추론 |
| 04 | 추적과 추종 판단 | Detection → Tracking → Target ID → Control command |
| 05 | PX4 연동 | MAVLink 명령과 Telemetry, SITL 검증 후 실기체 적용 |
| 06 | 통합과 시험평가 | 조건별 탐지·추적·추종, 지연과 전력 시험 |

### 1.3 문서 체계

ARGUS 기술문서는 MIL-STD-498 기반 방위사업청 작성가이드의 순서를 간략화하여 따른다. 시험계획(STP)은 STD 1~3장으로 갈음한다. 산출물 명칭과 저장소 안 파일 위치의 대응은 `docs/document_list.md` 를 따른다.

| 체계 설계 | SSDD | 체계 시험 | STD L3·L4 (실내·실외 비행) |

## 3. 체계 요구사항

검증 방법: T(시험) · D(입증/시연) · A(분석) · I(검사). 세부 수치는 하위 SRS 4장에서 정의한다.

### 3.1 운용 개념

- 운용자는 통제기에서 영상과 추적 결과를 보고 추종 대상 1개를 지정한다.
- 드론은 온보드에서 표적을 탐지·추적하고, 지정 대상을 자율 추종한다.
- 대상 소실·통신 단절·조종자 개입 시 자율 추종을 멈추고 정지(Hold) 또는 조종자 제어로 전환한다.
- 실기체 비행 전에 시뮬레이션과 기록 영상으로 기능을 검증한다.

### 3.2 기능·성능 요구사항

| ID | 요구사항 | 검증 | 검증 단계 |
|---|---|---|---|
| SSS-01 | 체계는 지휘부와의 통신 없이 온보드에서 지상 표적(전차)을 실시간 탐지해야 한다. | D | 인수 시험 |
| SSS-02 | 체계는 운용자가 지정한 표적 1개의 식별을 유지하며 추적해야 한다. | T | 통합 시험 |
| SSS-03 | 체계는 지정 표적을 자율 추종하기 위한 비행 명령을 비행제어기에 제공해야 한다. | D | 체계·인수 시험 |
| SSS-04 | 체계는 통제기 링크가 끊겨도 온보드 탐지·추적을 계속해야 한다. | T | 통합 시험 |
| SSS-05 | 체계는 영상 획득부터 비행 명령 송신까지 실시간 처리 성능을 가져야 한다. | T | 통합 시험 |
| SSS-06 | 체계는 운용자에게 영상·추적 결과·임무 상태를 제공하고, 표적 지정·추종 시작·중단 명령을 받아야 한다. | D | 인수 시험 |

## 4. 검증 규정

- 인수 시험: 운용 시나리오 시연으로 SSS-01·03·06을 확인한다.
- 체계 시험: 실내·실외 실기체 비행(STD L3·L4)으로 SSS-03·09·11·12·13을 확인한다.
- 통합 시험: SRS로 분해된 요구사항을 STD L1·L2 시험 케이스로 확인한다.
