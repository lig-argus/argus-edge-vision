# 전체 흐름도와 현재 구현 — 2026-09-26

기준 문서는 [상세 flow](design/flow.mmd)와 [전체 whole-flowchart](design/whole-flowchart.mmd)다. 두 파일은 PC의 원문을 수정하지 않고 복사했다.

## 현재 인지 경로

```mermaid
flowchart TD
    PROFILE[환경 프로파일] --> ROOT[CompositionRoot]
    ROOT --> SOURCE[IFrameSource]
    V4L2[V4L2 BGR uint8] --> SOURCE
    SDK[C++ SDK RAW14 캡처] --> RAW[RAW14 검증 / Gray8 / BGR3]
    RAW --> SOURCE
    FILE[유한 영상 Replay] --> SOURCE
    SOURCE --> QUEUE[기존 유계 FIFO / 용량 2]
    QUEUE --> PRE[Letterbox / BGR → RGB]
    PRE --> DET[Hailo 또는 Mock Detector]
    DET --> OBS[전체 박스 Observation / 시각 메타데이터]
    OBS --> BUS[perception/observations / ZeroMQ]
    BUS --> VIEW[구독자 / 미리보기]
    OBS -. 미구현 .-> TRACK[온보드 Tracker / FC 회전 CMC]
    TRACK -. 미구현 .-> DATA[tracking/tracks / ID별 실제 검출 시각 / TTL]
    DATA -. 미구현 .-> STORE[LatestStateStore / epoch]
    STORE -. 미구현 .-> CONTROL[독립 제어 / FSM / Guard / Watchdog]
    CONTROL -. 미구현 .-> PORT[단일 VehiclePort / PX4]
```

인지 루프는 명령을 생성하지 않는다. 현재 진입점 `vision_node`는 `perception_only` 진단을 발행하며 추적기나 PX4 제어가 작동한다고 표시하지 않는다. 점선 부품은 아직 없다.

## 입력과 부품을 교체하는 경계

`CompositionRoot.create_frame_source(options)`는 `profile.frame_source`를 실제로 사용한다. `ir_v4l2`, `ir_sdk`, `replay`가 구현돼 있다. Gazebo 입력은 미구현 오류를 낸다. `--frame-source`를 명시하면 입력 시험용으로 override할 수 있다.

새 입력은 `source_factories`에 `factory(options, clock)`를 등록하고 `IFrameSource.read()`가 `(ok, SourceFrame)`을 반환하도록 구현한다. 영상은 BGR uint8 3채널, 시각은 `FrameTiming`으로 전달한다. `request_stop()`과 `release()`가 종료를 책임진다.

Detector는 기존 `Detector` Protocol을 유지한다. Tracker와 VehiclePort는 각각 `tracker_factories` / `vehicle_factories`에 등록하고 `create_tracker()` / `create_vehicle_port()`로 선택한다. 이름만 지정하고 생성 요청을 하면 미구현 오류가 발생하며, 임의 Mock으로 대체하지 않는다. 실제 알고리즘·FC 어댑터는 다음 작업이다.

상세 flow의 추적기 후보는 ByteTrack, OC-SORT, Hybrid-SORT HMIoU OFF/ON 네 가지이며 시험마다 하나를 선택한다. 현재는 이름 검증과 등록 경계만 있다.

## 수정한 설계 계약

1. **시각:** 관측 메시지는 v2로 명시했고 새 수신기는 기존 v1의 노출 시각을 미확인으로 취급한다.  수신 시각과 실제 노출 시각을 분리했다. 현재 OpenCV/SDK는 노출 시각을 제공하지 않으므로 `exposure_time_valid=false`, `exposure_monotonic_ns=null`이다. FrameTiming과 DetectionFrame의 `require_exposure_time()`은 이 상태를 거부한다. 실제 노출 시각/FC 로그 동기화가 제공되기 전에는 정밀 CMC 정렬을 완료했다고 볼 수 없다.
2. **오류:** 카메라 연속 실패와 초기화 실패를 fault로 전달하고 실행 오류를 발생시킨다. Replay EOF는 별도로 정상 종료한다. 소스·Detector를 정리한다.
3. **조립:** 프로파일별 실제 입력 팩토리를 적용했다. 미구현 부품은 생성 요청 시 명확히 거부한다.
4. **트랙 TTL:** ID별 `last_real_detection_monotonic_ns`와 `ttl_ns`를 추가했다. 예측 갱신은 마지막 실제 검출 시각을 유지한다. 발행/배치 만료 갱신으로 이 TTL을 연장할 수 없다. TTL 기본 0은 만료이며 시험에서 값을 명시해야 한다.
5. **버스 종료:** 신호 핸들러는 종료 요청만 설정한다. 프록시 루프가 끝난 뒤 소켓을 먼저 닫고 Context를 종료한다.

## 유지한 정책과 검증 범위

기존 프레임 큐 코드와 용량 2는 유지했다. 이는 인지의 유계 FIFO이며 제어의 최신 상태 스냅샷과는 별개다. 전체 박스만 사용하고 hull ROI는 없다.

검증은 메시지·TTL·오류·Factory·실제 프록시 전달/종료, 합성 영상 Replay 및 C++ SDK 테스트 패턴으로 수행한다. 실제 카메라 영상·Hailo 추론 성능·CMC·추종 비행은 검증하지 않았다. 배포 전후 테스트 결과와 백업 위치는 PC의 변경 보고서에 별도로 보존한다.
